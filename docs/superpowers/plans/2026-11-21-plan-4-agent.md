# Kế hoạch 4: Trợ lý AI ở backend (LangGraph + Gemini)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** API trò chuyện với trợ lý AI. Trợ lý:
- gợi ý, so sánh gói từ DB; xem giờ trống;
- đặt lịch có bước dừng chờ xác nhận;
- hướng dẫn chuẩn bị (checklist + RAG);
- phát hiện cờ đỏ hai lớp;
- kiểm tra đầu ra, gắn disclaimer.

Khách chưa đăng nhập vẫn chat được (có giới hạn lượt), hội thoại chuyển sang tài khoản khi đăng nhập. Tư vấn viên xem được cảnh báo và đọc hội thoại.

**Architecture:**
- **Đồ thị LangGraph** `safety_check → agent ⇄ tools → output_guard` (spec mục 7). LLM gọi qua `init_chat_model` của LangChain, nên đổi nhà cung cấp chỉ cần sửa `.env`.
- **Tools** là `@tool` của LangChain, nhận DB session và người dùng qua tham số ẩn `InjectedToolArg`, trả `content_and_artifact`. Phần artifact chính là khối giao diện.
- **Node `tools` tự viết**, không dùng ToolNode có sẵn. Lý do: cần gom artifact thành `blocks`, nâng mức cờ đỏ và gọi `interrupt()` khi đặt lịch.
- **Checkpoint:** lưu ở Postgres bằng `PostgresSaver`. Mỗi hội thoại là một `thread_id`.
- **Test:** chạy bằng model giả, không gọi Gemini thật. Chỉ `scripts/run_eval.py` gọi Gemini thật.

**Tech Stack:** langgraph 1.2 (`StateGraph(..., context_schema=...)`, `Runtime`, `interrupt`, `Command`, `InMemorySaver`, `PostgresSaver`), langchain-core (`@tool`, `InjectedToolArg`, `GenericFakeChatModel`, `DeterministicFakeEmbedding`), langchain-google-genai, pgvector, psycopg_pool. Tất cả đã cài ở Kế hoạch 1.

**Spec:** `docs/superpowers/specs/2026-11-21-mediflow-ai-design.md` (mục 6 bảng `conversations`/`chat_messages`/`alerts`/`prep_chunks`; mục 7; mục 8; mục 9; mục 14; **mục 18: 3 lưu ý từ lần thử Gemini**)

**Điều kiện:** Kế hoạch 1, 2, 3 đã xong. `backend/.env` có `GOOGLE_API_KEY`, `LLM_MODEL=gemini-3.5-flash-lite`, `EMBEDDING_MODEL=gemini-embedding-2` (chỉ cần cho seed RAG thật và `run_eval.py`).

## Global Constraints

- **Ba lưu ý từ lần thử Gemini (spec mục 18):**
  1. System prompt luôn ghi ngày hôm nay theo giờ VN kèm thứ. Tool `get_available_slots` mặc định `date_from = today_vn()`.
  2. Tham số `purpose` là `Literal` các tag cố định.
  3. Giữ nguyên `AIMessage` của Gemini trong state (có `extras.signature`), không tự dựng lại. Ngoại lệ duy nhất: `output_guard` thay *câu trả lời cuối không có tool call* bằng message mới **cùng `id`**.
- **Thông tin gửi cho LLM:** chỉ tuổi, giới, ngữ cảnh trang và lời khách đã che PII (`pii.redact`). Không bao giờ gửi tên, email, SĐT.
- **Lưu tin nhắn:** `chat_messages.text` và `alerts.matched_text` luôn là bản đã che PII. Không ghi nội dung chat vào log.
- **Test:** không bao giờ gọi Gemini thật. Override `get_agent` và `get_embeddings` bằng bản giả.
- **Kiểm tra API LangGraph:** khi một tên API trong kế hoạch không khớp bản đã cài, kiểm tra bằng `uv run python -c "import inspect, langgraph.types as t; print(inspect.signature(t.interrupt))"` (hoặc tương tự), rồi ghi lại chỗ sai lệch trong ledger.
- **Kiểm tra mỗi task:** `cd backend; uv run pytest` và `uv run ruff check .` sạch sau mỗi task.
- **Commit:** message một dòng tiếng Việt, không có Co-Authored-By.

## Review Focus

1. **Gemini lỗi** (429 hết quota, 500, timeout): API vẫn trả 200 với câu xin lỗi tiếng Việt, tin nhắn của khách vẫn được lưu, không lộ lỗi gốc. → test ở Task 5.
2. **Resume sau khi khung giờ vừa hết chỗ** (`BookingError` lúc xác nhận): trợ lý báo "Khung giờ đã hết chỗ", không crash, không tạo lịch. → test ở Task 4.
3. **Gọi `/confirm` khi không có lịch chờ, hoặc gọi lần thứ hai** → 409, không đặt trùng. → test ở Task 5.
4. **Cookie khách của trình duyệt khác** không đọc được hội thoại (404). Đăng nhập khi đã có hội thoại khách thì hội thoại chuyển sang tài khoản, khách cũ hết quyền đọc. → test ở Task 5.
5. **Tin nhắn rỗng, toàn dấu cách, hoặc dài hơn 2000 ký tự** → 422 tiếng Việt, không gọi LLM, không trừ lượt. → test ở Task 5.

### Task 3: Tools của agent

**Files:**
- Modify: `backend/app/agent/state.py`, `backend/app/agent/tools.py`
- Test: `backend/tests/test_tools.py`

**Interfaces:**
- Consumes: `catalog`, `booking`, `prep`, `rag`, `red_flags`, `today_vn`, các schema `PackageSummary/PackageDetailOut/CompareOut/SlotOut/BookingOut/ChecklistItem`.
- Produces (`app.agent.state`):
  - `@dataclass class AgentContext`: `db: Session`, `user_id: int | None`, `user_age: int | None`, `user_gender: Literal["male", "female"] | None`, `embeddings: Embeddings`.
  - `class AgentState(TypedDict)`:
    - `messages: Annotated[list[AnyMessage], add_messages]`;
    - `user_context: dict` (`{"age", "gender"}`); `page_context: dict | None`;
    - `red_flag: Literal["emergency", "see_doctor"] | None`;
    - `alerts: list[dict]`, `blocks: list[dict]`: **không** gắn reducer, để mỗi lượt reset bằng giá trị đầu vào;
    - `tool_rounds: int`.
- Produces (`app.agent.tools`):
  - `Tag = Literal["tong-quat", "tim-mach", "ung-thu", "cao-tuoi", "tien-hon-nhan", "doanh-nghiep"]`, `SymptomCode = Literal[red_flags.SYMPTOM_CODES]`.
  - Mỗi tool là `@tool(response_format="content_and_artifact")`, có tham số ẩn `ctx: Annotated[AgentContext, InjectedToolArg]`. Docstring tiếng Việt là mô tả cho LLM. `content` là chuỗi ngắn để LLM đọc (JSON gọn), `artifact` là khối giao diện:

| Tool | Tham số cho LLM | Artifact |
|---|---|---|
| `search_packages` | `gender?`, `age?`, `purpose: Tag?`, `budget_max?`, `city?`, `hospital_code?`. Tuổi và giới mặc định lấy `ctx.user_age` / `ctx.user_gender` | `{"type": "packages", "packages": [PackageSummary…]}` (tối đa 6) |
| `list_hospitals` | `city?` | `{"type": "hospitals", "hospitals": [HospitalOut…]}` |
| `get_package_details` | `codes: list[str]` (1–3) | `{"type": "package_details", "packages": [PackageDetailOut…]}` |
| `compare_packages` | `codes: list[str]` (2–3) | `{"type": "compare", "data": CompareOut}` |
| `get_available_slots` | `package_code`, `date_from: date?` (mặc định `today_vn()`) | `{"type": "slots", "package_code", "slots": [SlotOut…]}` (tối đa 12) |
| `create_booking` | `package_code`, `slot_id` | xem bên dưới |
| `get_prep_checklist` | `package_code` | `{"type": "checklist", "package_code", "items": [ChecklistItem…]}` |
| `search_prep_docs` | `query` | `{"type": "sources", "items": [{"source", "title"}]}`; content = nội dung 3 chunk |
| `check_symptoms` | `symptom_codes: list[SymptomCode]` | `{"type": "red_flag", "severity": "emergency" \| "see_doctor" \| None, "hits": [{"rule_id", "severity", "matched"}]}` |

  - **`create_booking`:**
    1. Kiểm tra gói và khung giờ bằng `catalog.get_package` + `db.get(TimeSlot)`: cùng bệnh viện, chưa qua, còn chỗ. Sai thì trả `content` lỗi tiếng Việt, artifact `{"type": "error", "message"}`, **không** interrupt.
       - `message` lấy từ `ERROR_MESSAGES` cùng mã lỗi, ví dụ hết chỗ → `"Khung giờ đã hết chỗ"`.
       - Khi resume, LangGraph chạy lại node, nên bước kiểm tra này chạy lại và tự bắt được trường hợp khung giờ vừa hết chỗ.
    2. Đúng thì `decision = interrupt({"type": "confirm_booking", "package_code", "package_name", "hospital_name", "slot_id", "start_at", "price_vnd", "login_required": ctx.user_id is None})`. Mọi giá trị lấy từ DB.
    3. Khi resume:
       - `decision.get("approved")` và `ctx.user_id` có giá trị → `booking.create_booking(..., channel="assistant")` → artifact `{"type": "booked", "booking": BookingOut}`. Nếu gặp `BookingError` → artifact `{"type": "error", "message": <thông báo tiếng Việt cùng bảng với api/bookings._ERRORS>}`.
       - không xác nhận → content `"Khách chưa xác nhận đặt lịch."`, artifact `None`.
  - Lỗi của tool (`CatalogError`, `BookingError`, gói không tồn tại) trả `content` tiếng Việt, artifact `{"type": "error", "message"}`. Không raise ra ngoài.
  - Mọi `artifact` là dict thuần, JSON được: gọi `model_dump(mode="json")` trên các schema.
  - `TOOLS: list[BaseTool]`, `TOOLS_BY_NAME: dict[str, BaseTool]`.
  - `execute_tool_call(call: ToolCall, ctx: AgentContext) -> ToolMessage`:
    - gọi `TOOLS_BY_NAME[call["name"]].invoke({**call, "args": {**call["args"], "ctx": ctx}})`;
    - tool không tồn tại hoặc `ValidationError` → `ToolMessage(content="Lỗi tham số: …", status="error", tool_call_id=call["id"])`;
    - **không** bắt `GraphInterrupt`.
- Chuyển bảng thông báo lỗi `_ERRORS` từ `api/bookings.py` sang `app/services/booking.py` (tên `ERROR_MESSAGES`) để tool và API dùng chung; `api/bookings.py` import lại.
